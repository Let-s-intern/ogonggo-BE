# 오공고 서비스 개요

- 최종 변경일: 2026-10-09
- 예상 독자: 오공고를 처음 맡는 개발자
- 리뷰 상태: 팀 리뷰 필요

오공고를 처음 접하는 개발자가 코드를 읽기 전에 서비스의 모양을 잡을 수 있도록 정리한 문서입니다. 도메인 사이의 관계는 [도메인 개념도](domain-map.md)에, 용어와 코드 이름의 대응은 [용어 사전](glossary.md)에 있습니다.

## 1. 오공고는 무엇을 하는 서비스인가

> 취업을 준비하는 사람이 채용공고와 부트캠프를 한곳에서 찾아 지원 과정을 관리하고, 사이드 프로젝트·스터디 팀원을 모으고 취업 고민을 나누는 서비스입니다.

- **찾기**: 크롤러, 고용24, 기업 회원이 들여온 채용공고와 부트캠프를 직군·지역·고용 형태 등으로 거르고 정렬해 봅니다.
- **관리하기**: 마음에 드는 공고와 부트캠프를 북마크하고, 스크랩부터 합격까지 지원 단계를 직접 옮기며 관리합니다. 실제 지원은 원문 링크를 따라 외부에서 합니다.
- **함께하기**: 커뮤니티에서 사이드 프로젝트·스터디 모집글을 올리거나 취준고민 게시판에서 질문하고 답합니다.

오공고는 렛츠커리어와 연결된 서비스입니다. 일반 회원은 렛츠커리어 계정으로 로그인하며, 오공고에서 입력한 학력·희망 조건은 렛츠커리어로 보냅니다.

> 확인 필요: 서비스의 목표 사용자(대학생·사회초년생 범위 등)와 렛츠커리어와의 사업 관계는 기획 문서 기준으로 보완해 주세요.

## 2. 누가 사용하는가

| 사용자 | 코드 | 계정을 얻는 방법 | 주로 하는 일 |
| --- | --- | --- | --- |
| 일반 회원 | `UserRole.USER` | 렛츠커리어 로그인을 교환해 첫 로그인 때 자동 생성 | 공고·부트캠프 탐색, 북마크·지원 관리, 모집글·취준고민 작성 |
| 기업 회원 | `UserRole.COMPANY` | 오공고에서 이메일·비밀번호로 직접 가입 | 자기 회사의 채용공고·부트캠프 등록, 기업 프로필 관리 |
| 관리자 | `UserRole.ADMIN` | 관리자 콘솔(`ogonggo-api-admin`) | 기업 콘텐츠 검수, 콘텐츠 노출 관리, 오늘의 공고 선정, 공지 작성, 회원 관리 |
| 비로그인 방문자 | 없음 | 없음 | 공개된 콘텐츠 조회, 서비스 의견 작성 |

일반 회원과 기업 회원은 서로 무관한 계정이라 같은 사람이 둘 다 가질 수 있습니다. 인증 방식과 토큰은 [사용자 인증과 렛츠커리어 연동](../architecture/authentication.md)에 자세히 있습니다.

## 3. 콘텐츠는 어디서 들어오는가

채용공고와 부트캠프는 들어온 경로(`ContentSource`)가 정해지면 바뀌지 않으며, 경로에 따라 규칙이 다릅니다.

| 경로 | 코드 | 들여오는 방법 | 검수 |
| --- | --- | --- | --- |
| 크롤링 | `CRAWLER` | 외부 크롤러 서버가 내부 API 키로 관리자 API를 호출해 등록. 지금은 새싹 부트캠프와 채용공고를 수집 | 없음 |
| 고용24 | `WORK24` | 관리자 API의 스케줄 작업이 고용24 공공 API에서 채용공고와 KDT 과정을 주기적으로 수집 | 없음 |
| 비즈니스 등록 | `COMPANY` | 기업 회원이 사용자 API로 직접 등록 | 관리자 승인 후에만 노출 |

크롤러는 채용공고 본문을 AI로 분석한 **공고 분석**(`JobAnalysis`)도 만들어 보냅니다. 공고 본문이 바뀌면 분석을 숨기고 다시 분석할 대상이 됩니다.

## 4. 서버는 어떻게 나뉘는가

```text
ogonggo-api-user  ---> ogonggo-core <--- ogonggo-api-admin
```

| 모듈 | 누가 호출하는가 | 하는 일 |
| --- | --- | --- |
| `ogonggo-api-user` | 웹 클라이언트(일반 회원, 기업 회원, 비로그인 방문자) | 탐색·북마크·커뮤니티, 기업 회원의 콘텐츠 등록, 렛츠커리어 로그인 |
| `ogonggo-api-admin` | 관리자 콘솔, 크롤러 서버 | 검수·노출 관리, 공지, 회원 관리, 크롤러 수신, 고용24 수집 |
| `ogonggo-core` | 두 API 모듈 | 도메인 엔티티와 공통 비즈니스 규칙, JPA 영속성 |

두 API는 따로 배포하는 독립 애플리케이션입니다. 모듈 경계와 레이어 규칙은 [레이어와 모듈 아키텍처](../architecture/layers-and-modules.md)를 따릅니다.

## 5. 함께 연동하는 외부 시스템

| 시스템 | 연동 내용 |
| --- | --- |
| 렛츠커리어 | 로그인 토큰 교환, 프로필 동기화, 학력·희망 조건 전송, 추천 챌린지 조회, 일반 회원 비밀번호 변경 전달 |
| 고용24 | 채용공고·훈련 과정 수집 |
| 크롤러 서버 | 채용공고·부트캠프 등록, 공고 분석 전송, 분석 대상 조회 |
| 메일·Slack | 광고 문의를 담당자에게 전달 |
| Redis | 오공고 리프레시 토큰 보관 |

## 6. 주기적으로 도는 작업

| 작업 | 모듈 | 하는 일 |
| --- | --- | --- |
| 채용공고·부트캠프·모집글 자동 마감 | user | 마감일이 지난 콘텐츠를 모집 마감으로 바꿈 |
| 렛츠커리어 프로필 전송 | user | 전송 대기 중인 학력·희망 조건을 렛츠커리어로 보냄 |
| 이미지 정리 | user | 쓰이지 않는 업로드 이미지를 지움 |
| 고용24 수집 | admin | 고용24에서 채용공고·KDT 과정을 가져옴 |

실행 주기와 켜짐 여부는 DB에서 관리합니다. 자세한 내용은 [스케줄 작업](../architecture/scheduling.md)을 봅니다.
